About SupaWake

How it works — every part explained.

SupaWake is a free, open-source tool that keeps your Supabase free-tier projects alive automatically. No server needed. No paid plan required. This page explains everything in plain language.

The problem SupaWake solves

Supabase offers a generous free tier — but there is a catch. If no database activity occurs for 7 consecutive days, Supabase automatically pauses your entire project. That means your users get a broken app: sign-ups fail, logins fail, data cannot be read or written.

When someone visits your project link — a recruiter, a client, a friend — and tries to create an account, they get an error. They do not know about Supabase's pause mechanism. They just see a broken app. And they move on.

SupaWake solves this by sending a lightweight authenticated request directly to your Supabase database API every 5 days. That counts as real activity, the inactivity clock resets, and your project never pauses.

How SupaWake works — step by step

01

You sign in with Google

Your account is created instantly via Firebase Authentication. No password. No email verification. Your unique Google account ID is used to keep your projects private from other users.

02

You add your Supabase project

You paste your Supabase project URL (e.g. https://xyzabc.supabase.co) and your anon key. These are stored in Firebase Firestore, linked only to your account. No other user can see or access them.

03

GitHub Actions pings it every 5 days

A scheduled workflow runs automatically every 5 days. It reads your project list from Firestore and sends a GET request to each Supabase REST endpoint. Supabase logs this as activity and resets the 7-day clock. The status of each project is then updated in your dashboard.

04

You can also ping manually at any time

The Ping Now button on each project card triggers an immediate ping directly from your browser. You can use this once per day per project. The automatic schedule runs independently — manual pings do not affect the 5-day automatic cycle.

Using the Ping Now button

The ⚡ Ping Now button lets you instantly send a keepalive request to your Supabase project without waiting for the automatic schedule. It is useful when you are about to share a project link with someone and want to make sure the database is confirmed awake.

Rate limit

You can use Ping Now once per day per project. If you try again within 24 hours, SupaWake will tell you how many hours are left. This is to prevent accidental spam to your own database.

What happens when you click it

Your browser sends a GET request to your Supabase REST API with your anon key in the header. Supabase processes the request, logs it internally, and responds with a status code. SupaWake reads that code and updates your project status to Awake or Error.

Verify that a ping worked — SQL guide

If you want to confirm that SupaWake's pings are actually reaching your Supabase database, you can run a query in your Supabase SQL Editor. Here is how.

Step 1 — Open Supabase SQL Editor

Go to app.supabase.com → open your project → click SQL Editor in the left sidebar → click New query.

Step 2 — Run this query

SQL — Supabase SQL Editor 
SELECT
  id,
  method,
  path,
  response_status,
  created_at
FROM net._http_response
WHERE created_at > now() - interval '7 days'
ORDER BY created_at DESC
LIMIT 20;

Step 3 — Read the results

The query returns a table like this. A SupaWake ping will appear as a row with response_status 200 or 204:

idpathstatuscreated_at
1/rest/v1/2002025-06-01 08:03
2/rest/v1/2002025-05-27 08:02

What every part of this SQL means

PartWhat it does
SELECTChooses which columns to return. We are selecting the row ID, HTTP method, URL path, response status code, and the timestamp of the request.
FROM net._http_responseThis is a built-in Supabase internal table that logs all HTTP requests made to your project's REST API. You are not accessing anyone else's data — only your own project's logs.
WHERE created_at > now() - interval '7 days'Filters results to only show activity from the last 7 days so the results are relevant and readable. You can change '7 days' to '30 days' if you want to see further back.
ORDER BY created_at DESCSorts results so the most recent ping appears at the top of the table.
LIMIT 20Returns a maximum of 20 rows. This prevents the query from returning thousands of rows if your database has a lot of activity. You can increase this number if needed.
response_status 200 or 204These are HTTP success codes. 200 means "OK — the request was received and processed". 204 means "No Content — the request was received successfully but there is no data to return". Both confirm the ping worked.

This query is read-only. It does not modify any data, does not grant access to anything, and does not expose any information beyond your own project's request logs. It is equivalent to checking your own server access logs.

Security — how your data is protected

🔐

Firebase Authentication

You must be signed in to access anything. Anonymous access to Firestore is blocked entirely by the security rules. Nobody can read the database without a valid Google account session.

🛡️

Firestore Security Rules

Every project document is tagged with your unique Google account ID. The Firestore rules reject any query where the requesting user's ID does not match the document owner's ID. You physically cannot see another user's projects — the request is blocked at the server level before any data is returned.

🔑

Anon Key is safe to store

The Supabase anon key is designed to be public. It is embedded in every Supabase frontend app — including yours. Real security comes from Row Level Security policies on your tables, not from keeping the anon key hidden.

⚠️

Never store your service_role key

The service_role key bypasses Row Level Security entirely. SupaWake explicitly warns against entering it and will flag it if detected. Only ever paste your anon key into SupaWake.

Open source & transparent

SupaWake is fully open source. Every line of code — the frontend, the GitHub Actions workflow, the Firestore rules — is visible in the public repository. You can inspect exactly what happens when a ping is sent and verify that nothing beyond a simple HTTP request is made to your Supabase project.
